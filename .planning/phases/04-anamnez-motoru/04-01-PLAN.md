<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/templates, /api/sessions | Untrusted admin/dentist input crosses into DB writes (handled in 04-02/04-04; schema must not rely on app-layer validation alone) |
| stored session → completion | Consent flags must be true before status='completed' |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | sessions.status set to 'completed' bypassing consent | mitigate | DB CHECK `sessions_consent_required_when_completed` — DB rejects completion without both consent flags, independent of API code |
| T-04-02 | Information Disclosure | cross-user template/answer reads | mitigate | RLS `user_isolation` policy on all 4 tables + app-layer `.eq('user_id', userId)` (defense-in-depth per pivot pattern) |
| T-04-03 | Tampering | mutating a published template version breaks saved sessions | mitigate | template_versions is insert-only (immutable); sessions reference template_version_id snapshot, never live template_questions |
| T-04-04 | Information Disclosure | patient health data (answers) is KVKK special category | accept | Stored in user-scoped table behind RLS; no audio retention; encryption-at-rest is Supabase platform default |
</threat_model>
