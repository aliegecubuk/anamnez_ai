## Screen Contracts

### Screen 1: Patient List — /orgs/[slug]/patients

Layout:
- Full-width content area inside existing org layout (sidebar + top nav from Phase 1)
- Page header row: heading "Hastalar" (20px, weight 600) left + "Yeni Hasta" button (accent, right-aligned)
- Search bar below header: full-width Input with magnifier icon (lucide `Search`), placeholder "Ad veya TC ile ara..."
- Patient table below search, full width
- Empty state below search when no results

Patient table columns:
| Column | Content | Width |
|--------|---------|-------|
| Ad Soyad | Full name | flex-1 |
| TC Kimlik No | Masked: `••••••••• XX` (last 2 digits) | 160px |
| Son Seans | Date of most recent session (dd.MM.yyyy) or "—" | 140px |
| İşlemler | "Görüntüle" link button | 100px |

Table behavior:
- Clicking any row navigates to /orgs/[slug]/patients/[id]
- "Görüntüle" button also navigates to patient profile
- Row hover: --secondary (#F1F5F9) background
- No row selection / bulk actions in this phase
- Sorted by last name ascending by default

Search behavior:
- Client-side debounce: 300ms after last keystroke before triggering search
- Searches both full name (case-insensitive) and TC kimlik no (exact prefix match)
- Results update in-place (no page reload)
- Clear button (lucide `X`) appears inside input when value is non-empty

### Screen 2: Create Patient Dialog

Trigger: "Yeni Hasta" button on patient list.

Dialog spec:
- `<Dialog>` component, max-width 480px, centered
- Title: "Yeni Hasta Oluştur" (heading size, weight 600)
- Description: "Hasta kaydı oluşturmak için ad soyad ve TC kimlik numarasını girin."
- Form fields (vertical stack, 16px gap):
  1. Ad Soyad — text input, required, placeholder "Örn: Ayşe Kaya", max 100 chars
  2. TC Kimlik No — text input (type="text" not "number"), required, placeholder "11 haneli TC kimlik numarası", pattern `[0-9]{11}`, maxLength 11
     - Input font: Geist Mono (monospace — digit clarity)
     - Real-time length counter: "X/11" displayed as helper text below field
     - Validation fires on blur AND on submit attempt
- Error messages (inline, below field, 14px, weight 400, --destructive color):
  - Ad Soyad empty: "Ad soyad zorunludur."
  - TC Kimlik No empty: "TC kimlik numarası zorunludur."
  - TC Kimlik No invalid length: "TC kimlik numarası tam 11 haneli olmalıdır."
  - TC Kimlik No non-numeric: "TC kimlik numarası yalnızca rakam içermelidir."
  - TC already exists: "Bu TC kimlik numarasıyla kayıtlı bir hasta zaten var."
- Dialog footer (right-aligned, 8px gap):
  - "İptal" — ghost variant button, closes dialog, discards form
  - "Oluştur" — accent primary button, submits form
    - Loading state: disabled + lucide `Loader2` spinning icon + "Oluşturuluyor..." label
- On success: dialog closes, toast "Hasta başarıyla oluşturuldu." (sonner success), patient list refreshes, new patient row highlighted briefly (200ms --secondary flash)
- On server error: toast "Hasta oluşturulamadı. Lütfen tekrar deneyin." (sonner error), dialog stays open

### Screen 3: Patient Profile — /orgs/[slug]/patients/[id]

Layout:
- Same org layout shell (sidebar + top nav)
- Breadcrumb: "Hastalar" (link) › "Ad Soyad" (current, truncated at 30 chars)
- Patient header card (`<Card>`, full-width):
  - Left: patient initials avatar (40×40px circle, --secondary bg, --foreground text, weight 600, 16px)
  - Right of avatar: name (20px, weight 600) + TC masked "TC: ••••••••• XX" (14px, --muted-foreground, Geist Mono for digit portion)
  - Far right: "Yeni Seans Başlat" button (accent primary, 44px min-height)
- `<Separator>` below card (16px margin top and bottom)
- Section heading "Seans Geçmişi" (16px, weight 600) + session count badge (e.g., "3 seans", --secondary bg)
- Session history table (full-width) or empty state

Session history table columns:
| Column | Content | Width |
|--------|---------|-------|
| Tarih | dd.MM.yyyy HH:mm | 160px |
| Form Tipi | `<Badge>` with type label | 140px |
| Durum | "Tamamlandı" / "Taslak" badge | 120px |
| İşlemler | "Görüntüle" button | 100px |

Form type badge colors (using existing badge variants):
- "Anamnez" — default (neutral)
- "Perio" — outline with --primary color
- "Patoloji" — outline with --warning color
- "Genel" — secondary

Session rows sorted: most recent first.
"Görüntüle" navigates to the session view (route defined in Phase 4/6a/6b — for now, stub link or disabled).

## KVKK / PII Display Rules

These are interaction contracts, not just data rules:

1. TC kimlik no is NEVER displayed in full on any list or profile view. Always masked: `••••••••• XX` (last 2 digits visible).
2. TC kimlik no is shown in full only inside the create dialog "TC Kimlik No" input while the user is actively entering it.
3. No patient name or TC appears in page `<title>` tags or browser tab titles (prevents shoulder-surfing exposure).
4. Breadcrumb shows patient name (acceptable — clinical context, clinician is authenticated), not TC.
5. Search query containing TC digits: results display but the matched TC is not highlighted/echoed in the results.
