<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase anon key → DB | Anon key must not be able to read any tenant data |
| service_role key → DB | Bypasses all RLS — must never reach client bundle |
| Tenant A JWT → Tenant B rows | Cross-tenant data access must be impossible at DB layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `public.tenants` RLS (no policies) | mitigate | No user-facing SELECT policy on tenants table. Only service_role reads tenant list. Anon/authenticated roles get 0 rows via anon key. |
| T-02-02 | Information Disclosure | `public.login_audit_log` RLS | mitigate | No user-facing SELECT or INSERT policy. Only service_role (supabaseAdmin) inserts audit records. Tenants cannot read each other's or their own login history via API. |
| T-02-03 | Elevation of Privilege | RLS bypass via `auth.jwt() ->> 'org_id'` null | mitigate | When org_id is null (no active org), subquery `WHERE clerk_org_id = NULL` matches nothing — RLS correctly returns 0 rows. Tested via seed.sql test tenants. |
| T-02-04 | Tampering | Migration order tampering | mitigate | Migration filenames include timestamp prefix (20260501000001, 20260501000002). Supabase CLI applies in lexicographic order. Foreign key constraints enforce order. |
| T-02-05 | Information Disclosure | service_role key in seed.sql | accept | seed.sql contains only fake test org IDs (org_test_tenant_a). No real credentials. seed.sql is committed to git — confirmed safe content only. |
</threat_model>
